# Support and beta feedback

AirWiki is an early technical beta, not a supported stable product. The best
way to help is to report a reproducible result using only synthetic material.

## Choose the right channel

| Need | Channel | What to include |
| --- | --- | --- |
| Reproducible defect | [Bug report](https://github.com/airwiki/airwiki/issues/new?template=bug_report.yml) | Version, platform, synthetic steps, expected and actual result |
| Product idea or workflow feedback | [Feature request](https://github.com/airwiki/airwiki/issues/new?template=feature_request.yml) | Problem, intended outcome, alternatives considered |
| Setup or usage question | [Question](https://github.com/airwiki/airwiki/issues/new?template=question.yml) | Goal, platform, what you tried, only sanitized details |
| Potential vulnerability or exposure | [Private vulnerability report](https://github.com/airwiki/airwiki/security/advisories/new) | Follow [SECURITY.md](SECURITY.md); never report security issues publicly |

Issues are public. Do not include real documents, query text, search snippets,
screenshots, logs, databases, credentials, device names, network addresses,
local paths, or other personal or confidential information. Replace every
example with a minimal synthetic reproduction.

## What to expect during the beta

The project does not currently offer a support-level agreement, response-time
commitment, recovery service, or compatibility promise. Maintainers may ask for
a smaller synthetic reproduction, close reports that cannot be reproduced, or
defer work to the [beta roadmap](ROADMAP.md). Public technical pre-releases are
unsupported test candidates; see [FAQ.md](FAQ.md) and [docs/install.md](docs/install.md)
before installing one.

## Before filing

1. Confirm that the behavior is not listed in [FAQ.md](FAQ.md) or the current
   [known limitations](FAQ.md#known-limitations).
2. Check [open issues](https://github.com/airwiki/airwiki/issues) for an
   existing report.
3. Reproduce the behavior with synthetic files and a current technical beta or
   a source build from a specific commit.
4. Include the smallest safe set of steps and sanitized PASS/FAIL facts.

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). Its
private enforcement contact is not yet published; that remains a release
blocker. Do not use public issues to report conduct incidents.
